# CH-W21W22-media: Wave 5 adversarial review (W21 + W22 media)

Challenger: Opus 5.5, role W21 + W22 (media), per `../03-wave5-challenger-brief.md`. Attack surface: confusion between source and asset (an asset used as evidence without a locator path, rendition timecodes reused across renditions, a retelling counted as independent, rights UNKNOWN read as permission, a generated or edited image that EVIDENCES something), together with the W21 speech-act and correction seams. Mutations, probes and undos are in `CH-W21W22-media.cypher` (`// ==== CH-M-nn APPLY | PROBE | UNDO ====` blocks).

## Execution scope (RUN)

- **Instance.** Isolated Neo4j 5.26.31 Community instance `c4` (embedded, APOC core). It came preloaded with `docs/schema/neo4j/final_biotech_schema_operations.cypher`, the six translated 0.2.0 fixtures and the backfill.
- **Group load.** I loaded the W21 positives fx01, fx02b, fx03, fx04, fx05, fx06 and fx07 into the same graph, then W22 mp1–mp6. All 591 statements succeeded. W21 runs each fixture in a fresh graph. fx02a shares uids with fx02b and was therefore **not loaded**; CH-M-12 rebuilds the fx02a shape on fresh uids instead. The W21 `.neg.cypher` files were not re-run because they have no undo; the Wave 6 plan already covers them.
- **Validators after every APPLY.** Four suites ran each time:
  - `docs/schema/neo4j/validation.cypher` with `validation-params.json`
  - `workers/W00/validation-corrections.cypher`
  - `workers/W21/fixtures/w21-validation.cypher`
  - `workers/W22/fixtures/v-media-validation.cypher`

  "Observed" below is the row difference against a validator run taken immediately **before** each APPLY. That run was taken per objection because `validation-corrections.cypher` changed on disk during this session (43 → 44 statements). Changes that only touch informational counts (V-118, V-514b) are omitted. After every UNDO the validators were back at their pre-APPLY rows. The instance is left with the group-loaded fixtures and none of the challenger nodes.
- **Baseline rows caused by the group load itself** (not by challenger mutations). These are reported because they are real collisions between fixtures:
  - V-402 = 1: `hu:locator:synthetic-digest-retelling` hangs from two snapshots, because fx04 and the translated claim-retelling fixture attach the same locator uid to different snapshots.
  - V-110 = 2.
  - Kernel V-423 = 1 on the valid fx07 projection (see CH-M-17).
  - The two fixtures mint two primary ClaimOccurrence uids for the same Sinclair utterance (see CH-M-08).

## What held

- **SUPPORTED_BY straight to a media node** is caught by V-615 (CH-M-05).
- **An IMAGE_REGION locator with no snapshot** is caught by kernel V-402 (CH-M-04), although V-604 alone would accept it.
- **A legacy `HAS_VARIANT` edge** on a media asset is caught by V-101, or by V-505r once the profile is copied (CH-M-03). This is incidental, not by the media rule.
- **W22 embedded negatives fire as documented on the group load:**
  - V-601 dangling region
  - V-602 crop or overlay bytes ≠ snapshot (2)
  - V-604 / V-605 for the hand-written EVIDENCES from the `GENERATED` illustration
  - V-606 (2)
  - V-608 unauthorized display
  - V-608b authorized display without a permitting rights record
  - V-610 legacy scores
  - V-112 / V-112r `EVIDENCES` with no citation.
- **The rights gate holds for every non-null status:**
  - ALL_RIGHTS_RESERVED, NO_STATEMENT_FOUND and RESTRICTED_TERMS are excluded.
  - "Never checked" is excluded.
  - The freely readable Elsevier figure stays not-permitted (Q-MP4-1, Q-MP4-2). It fails only on null (CH-M-14) and on the duty Booleans (CH-M-15).
- **Linked retellings are handled correctly:** Q04-1 / Q-06 exclude assertions with an outgoing `RETELLS`. V-412 / V-413 / V-410 guard the shape of the link. The gaps are an unlinked retelling and duplicate occurrences (CH-M-07, CH-M-08).
- **Every CH-M undo restored the pre-APPLY validator rows exactly.**

## Not tested / limits

- **Enterprise.** `media_rights_record_rights_status_exists` and the other existence constraints in `final_biotech_schema_operations.enterprise.cypher` were not exercised (no Enterprise instance). They would reject CH-M-14's write. They would not reject CH-M-15, and they do not close the three-valued-logic hole in Q-MP4-1, which also reads `[x IN recs | …]` over OPTIONAL matches.
- **GraphQL layer.** No API server ran in this scope. By reading the SDL, `Claim.occurrences` and `Claim.assertionInstances` both traverse every incoming `INSTANCE_OF`, so retellings, duplicates and SUPERSEDED instances all appear, and ClaimOccurrence nodes appear in both lists. Any API-side count of corroboration therefore inherits CH-M-07 and CH-M-08. This was not executed.
- **W21 `.neg.cypher` files and fx02a** were not re-run here (see Execution scope). W21's documented catches for N01…N06 were not re-verified on the assembled suite in this instance.
- **Privacy.** No media privacy case was attacked: no private node is reachable from media in these fixtures, and W23 owns the leak tests. No BLOCKING privacy finding.
