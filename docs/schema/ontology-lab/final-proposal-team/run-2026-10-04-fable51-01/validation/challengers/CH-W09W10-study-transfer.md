Challenger: Opus 5.5 in the W09 + W10 role, run `run-2026-10-04-fable51-01`, 2026-10-04. Attack surface: the assembled artifacts, meaning `docs/schema/final_biotech_schema_proposal.graphql` (W09 and W10 banners), `docs/schema/neo4j/final_biotech_schema_operations.cypher` and the compiled validation suite. The suite is the set the Wave 6 plan runs for W09 and W10: `docs/schema/neo4j/validation.cypher` (0.2.0, 174 statements), `workers/W00/validation-corrections.cypher` (V-211r, V-215r, V-217r, V-221r, V-108r, V-508r, V-112r and the rest), `workers/W09/fixtures/80-queries.cypher` (V-W09-01..11) and `workers/W10/operations.cypher` Part B (W10-V01..V16b). The mutations and undos are in `CH-W09W10-study-transfer.cypher` next to this file. Every statement in that file passes EXPLAIN (61 of 61).

**Execution.** All runs used isolated instance `c3`: embedded Neo4j 5.26.31 Community with APOC core. The instance was preloaded with the final operations file, the six translated 0.2.0 fixtures (including study-vs-product-mismatch) and the 99 backfill. I then loaded the W09 fixtures 01–07 (70 of 70 statements OK) and the W10 fixtures w10-01..05 (68 of 68 OK), in the documented order. Baseline: I ran all four validator files (267 statements, 0 errors) and recorded the row count of every check. Each attack was then run alone: apply → rerun the four files → diff the counts per check label → undo. After the last undo the suite matched the baseline exactly, and `MATCH (n) WHERE n.uid CONTAINS 'ch-s-' RETURN count(n)` returned 0.

For GraphQL, `harness/roundtrip.mjs` built the final SDL with @neo4j/graphql 7.6.3 (41.7 s) and executed 13 write operations against the same database. The operations are listed in the .cypher file as comments, each with its observed result.

**Reading "caught".** A check counts as catching an attack only if its row count changed and the new row names the attack's element. Rows that fire on an unrelated defect are reported as collateral. Example: V-505r fires when an authorizing assertion lacks its valid time. I removed such collateral where an attacker would have avoided it; CH-S-01 and CH-S-03 were re-run after that change. Informational checks (V-108r, V-509r, V-505i, QS-*) are review rows, not violations.

**Severity.** BLOCKING is used only for a failing shared-contract or privacy case: contract A5/D-011 (derived edges), A6 (recorded time is never backdated) and A9 (privacy). Every other uncaught case is MAJOR when it lets study evidence reach a product, verdict or replication count it should not reach, and MINOR otherwise.

The texts are in this file's table. V-201r and V-218r are written out in full below.

```cypher
// V-201r (proposed)
MATCH (s)-[r]-(p)
WHERE (s:Study OR s:StudyArm OR s:StudyIntervention OR s:InterventionComponent OR s:StudyResult OR s:Publication OR s:Dataset
       OR s:OutcomeDefinition OR s:StudyPopulation OR s:RegistrationVersion OR s:TrialRegistration OR s:ProtocolVersion)
  AND (p:Product OR p:ProductVariant OR p:FormulationVersion OR p:PackageConfiguration OR p:ProductLot OR p:MerchantListing
       OR p:Offer OR p:ConsumerBrand OR p:Bundle)
  AND NOT (s:InterventionComponent AND type(r) = 'USES_INTERVENTION_MATERIAL' AND startNode(r) = s AND (p:ProductVariant OR p:ProductLot))
RETURN DISTINCT 'V-201r' AS check, s.uid AS studySide, type(r) AS rel, p.uid AS commercial;

// V-218r (proposed)
MATCH (syn:EvidenceSynthesis)-[:INCLUDES_RESULT {inputRole: 'INDEPENDENT_REPLICATION'}]->(r:StudyResult)-[:RESULT_FOR]->(:OutcomeDefinition)<-[:DEFINES_OUTCOME]-(s:Study)
OPTIONAL MATCH (s)-[:PRODUCED_DATASET]->(d1:Dataset)
OPTIONAL MATCH (s)<-[:REPORTS_ON]-(:Publication)-[:ANALYZES_DATASET]->(d2:Dataset)
WITH syn, r, s, collect(DISTINCT d1.uid) + collect(DISTINCT d2.uid) AS ds
WITH syn, collect({r: r.uid, s: s.uid, ds: ds}) AS inputs
UNWIND inputs AS a
UNWIND inputs AS b
WITH syn, a, b WHERE a.r < b.r AND (a.s = b.s OR any(x IN a.ds WHERE x IN b.ds))
RETURN 'V-218r' AS check, syn.uid AS synthesis, a.r AS result1, b.r AS result2;
```

## 2. What held

- **The GraphQL write surface for the read-only legacy and derived fields held.** The input types of @neo4j/graphql 7.6.3 omit these fields, so each of the following writes was rejected:
  - `Study.evaluates` (LEGACY_EVALUATES), on update and on create;
  - `Study.sponsoredBy` and `Organization.sponsorsStudies` (derived SPONSORED_BY);
  - `SafetySignal.reportedInStudies` (derived REPORTS_SAFETY_SIGNAL);
  - the `Study.overallStatus` cache;
  - `EvidenceApplicability.doseMatch`;
  - `EvidenceSynthesis.verdict` on update.
