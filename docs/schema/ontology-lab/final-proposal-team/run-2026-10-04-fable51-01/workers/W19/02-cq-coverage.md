## 2. Candidate CQs (this packet)

### CQ-PV-C01 (candidate; proposed priority Foundational, Q): authority by claim scope

- **Desire.** "Is the source behind this statement the kind of source that can establish this kind of claim?"
- **Example answer.** "No authoritative source: the OPERATING capability state rests only on a securities filing assessed SELF_DECLARATION (method w19-authority-scope-v0.1), which the registry pattern marks notAuthorityFor `actual_facility_operations`, `capacity`. The registry's has_results=false supports 'results not posted', not 'results unpublished'."
- **Distinction.** source kind (endpoint genre) vs authority scope (claim type) vs truth. V-324 accepts any non-marketing source for an OPERATING state; a 10-K is non-marketing, so V-324 passes it.
- **Evidence.** `SourceAuthorityAssessment` with method version; predicate → required scopes table (proposed catalog convention, W19-SR-04).
- **Model.** `AuthorityScope`, `SourceAuthorityAssessment`, `ASSESSES_SOURCE_AUTHORITY`, `ASSESSED_ON_SNAPSHOT`.
- **Query.** Q-15. Expected: 2 × NO_AUTHORITATIVE_SOURCE (synthetic 10-K capability; registry RESULTS_PUBLISHED), 3 × AUTHORITATIVE_SOURCE_PRESENT.
- **Failing case without it.** The filing-sourced capability assertion and the registry-sourced "unpublished" assertion pass every existing validator.
- **Never.** It does not change `Assertion.status` or an Adjudication verdict; it routes the assertion to review.

### CQ-PV-C02 (candidate; proposed Foundational, A): coverage and freshness

- **Desire.** "For this subject, were the required sources captured, and is the newest capture fresh enough as of R?"
- **Example answer.** "At R = 2026-10-05: registry record FRESH (observed 2026-10-04), record history BLOCKED; PubMed revision status FRESH for PMID 29184669 and 30155270. At R = 2027-03-01: all STALE."
- **Distinction.** stale vs missing vs blocked vs not attempted; operational status vs truth.
- **Evidence.** `SourceCoverageRequirement` (kinds, scopes, max age, history required), snapshots' `observedAt` and `retrievedAt`, discovery records.
- **Model.** `SourceCoverageRequirement`, `FOR_COVERAGE_REQUIREMENT`.
- **Query.** Q-13a, Q-13b; truth separation Q-14a/b.
- **Failing case without it.** QS-2 `OPEN_END_STALE` handles open valid-time ends of assertions; it cannot say that a *required* source was never captured, or that a 5-month-old registry snapshot is too old for a registry fact, or that history retrieval was blocked.

### CQ-PV-C03 (candidate; proposed Foundational, A): discovery outcome

- **Desire.** "Did anyone look for this source, and was it found, not found, blocked, or only partly read?"
- **Example answer.** "ClinicalTrials.gov history for NCT02678611: BLOCKED (2026-10-04; HTTP 200 with an error page). API v2: BLOCKED (egress 403). Huberman Lab RSS item for episode 52: PARTIAL (feed truncated by the tool)."
- **Distinction.** BLOCKED vs NOT_FOUND vs PARTIAL vs ERROR vs NOT_ATTEMPTED (no record); 200-with-error-page is BLOCKED.
- **Model.** `SourceDiscoveryRecord` (Activity specialization), `DiscoveryOutcome`, `DISCOVERED_SOURCE`.
- **Query.** Q-13a (`historyCoverage`), Q-17 (`historyRetrieval`), Q-08c.
- **Failing case without it.** Absence of `RegistrationVersion` history reads as "the registry never changed", so an outcome-switching question (CQ-ST-04) is answered "no changes".
