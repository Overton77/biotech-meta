## GraphQL round trip (run, `@neo4j/graphql` 7.6.3 against the loaded data)

- Reads succeed over Cypher-ingested nodes: `productLots(where: {lotCode: {eq: "P098-01"}})` with `lotOf`, `certifiedUnder`; `certificateOfAnalyses` with `issuedByLab`, `certifiesExecutions { usedMethod producedResults }` (two fields of one relationship type to different targets resolve correctly); `certificationScopes { covers { __typename ... on ProductLot } }` over the union; `passFailInterpretations(where: {verdictBasis: {eq: SOURCE_STATED}, resultValueReported: {eq: NOT_REPORTED}})` returns the 7 pass-only verdicts with empty `interpretsResult`.
- **Finding 1 (runtime):** selecting any `DateTime` field (for example `expiryDate`, `createdAt`) fails with `Unknown function 'apoc.date.convertFormat'`: the 7.6.3 translation calls APOC for DateTime output, and the run's embedded 5.26.31 instance has no APOC. Deployment needs the APOC core plugin (or every DateTime read fails). Not specific to W12; reported for Fable's runtime gates.
- **Finding 2 (identity):** `createTestMethods` autogenerates `id` (`@id`, UUID) and the create input has no `id` field, so an API-created node's `id` is not the opaque segment of the caller-supplied `uid` (INV-106/V-117 break). Either the write service derives `uid` from the generated `id`, or `@id` autogeneration is dropped for types written through the API. Seam W12-SR-11 (W00). The probe node was deleted after the test.
