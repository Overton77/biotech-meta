# W05 operations recommendation

Target as declared by the run: Neo4j **5.26.31 Community** (embedded, tested), `@neo4j/graphql` **7.6.3**, `graphql` 16.14.2, `neo4j-driver` 6.2.0, Node 22. Enterprise behaviour unverified. No runtime implementation is delivered; statements below are recommendations for Fable's operations file, written with **stored** property names. The Community-runnable statement set is in `operations.cypher`; `fixtures/w05-09-constraint-probe.cypher` tests it.

## 2. Retrieval patterns

- CQ-FL-C01: start at `InterventionComponent`/`IngredientComponent` → `FoodItem` (base) → `VARIANT_OF` (incoming) → `QUANTITATIVELY_CONTAINS` → locator. Bounded depth (1 variant hop). One row per source assertion; never aggregate across sources without an assessment.
- CQ-FL-C02: start at the agent (`ChemicalSubstance`/`IngredientMaterial`/`Lifestyle`) → incoming `HAS_EXPOSURE_AGENT`; separately `ProtocolStep -USES->` the agent; union in the answer, never joined by an edge.
- CQ-FL-C03: product path is W04's; derived `CONTAINS` gives the shortcut, regenerable.
- CQ-RC-05: `Assertion` with `speechAct`; the `RECOMMENDS` edge only for `RECOMMENDS` speech acts.

## 3. Application validation (service-enforced; SDL does not enforce)

| Rule | Check | Transaction behaviour |
|---|---|---|
| Exposure tuple immutable | reject `SET` of tuple fields after commit; a change creates a new Exposure | write path: compute `characterizationHash` (rule below), `MERGE (e:Exposure {characterizationHash: $h})`; on conflict return existing uid |
| Exposure intensity complete | `intensityValue` ⇒ `intensityUnitCode` (UCUM-valid) and `intensityBasis` (V-W05-03) | reject |
| Exposure has ≥1 agent | create Exposure and its `HAS_EXPOSURE_AGENT` edges in one transaction (V-W05-04) | atomic |
| Exposure is not an occurrence | no `startedAt`/`endedAt`/`observedAt`, no edge to Person/CohortParticipant/actors/PrivateRecord (V-W05-06) | reject |
| FoodItem labels | `FoodItem` always with `IngredientMaterial`, uid prefix `hu:material:` (V-W05-02) | reject |
| foodGroup with system | V-W05-05 | reject on new writes; audit legacy |
| composition qualifiers | food `QUANTITATIVELY_CONTAINS` needs `valueDerivation`; per-100 basis needs reference amount and unit (V-W05-07, V-006) | reject |
| underived zeros | a source row with zero and no derivation is stored as an UNRESOLVED assertion with no projected edge | ingestion rule |
| VARIANT_OF | asserted (assertionUid of a `VARIANT_OF` assertion), acyclic (V-W05-08); check for a path `(b)-[:VARIANT_OF*]->(v)` before commit | serialize writes per base food (lock the base node: `SET b._lock = timestamp()` pattern or `CALL apoc.lock` is unavailable without APOC; use a write on the base node in the same transaction) |
| no step–exposure edge | V-W05-10 | reject |
| retired types/edges | no `FoodProduct` label, no `INVOLVES` from Exposure, no `CONTAINS_COMPOUND`/`HAS_INGREDIENT` (V-W05-01, V-W05-11) | reject; migration completeness audit |
| product identity on food | no `IDENTIFIED_BY` TradeItemIdentifier, `HAS_VARIANT`, `HAS_FORMULATION_VERSION`, `LISTING_FOR` on a FoodItem (V-W05-12) | reject |
| recommendation projection | W21 projection job writes `RECOMMENDS` only from `speechAct RECOMMENDS` (V-423, V-W05-09) | job-level check |

Rule `exposure-tuple/v1`: canonical JSON (keys sorted, no whitespace) of `{agents: sorted agent uids, route, durationCategory, durationIso, intensityValue (decimal string or null), intensityUnitCode, intensityBasis, setting, mediumText (NFC-WS1 normalized or null)}`; `characterizationHash = 'sha256:' + hex(sha256(utf8(json)))`. Text fields (`durationText`, `intensityText`, `frequencyText`) are excluded so a re-capture with different wording of the same tuple is idempotent; differing wording is kept on the authorizing assertions.

Concurrency: the uniqueness constraint on `characterizationHash` makes concurrent creation of the same Exposure fail for the second writer; the service retries as a read. Composition edges are keyed by `relationshipUid` (one per assertion), so concurrent ingestion of two sources never collides.

## 4. Migration and compatibility (M-W05-01..06)

Order: (1) W02 migrates `Ingredient`/`Compound`; (2) M-W05-04 relabel `FoodItem` (add `IngredientMaterial`, `Entity`; set `uid`, `entityType`, `materialKind`); (3) M-W05-01 relabel `FoodProduct` → `Product` (fixture 03 statement); (4) M-W05-03 rebuild product composition then delete `HAS_INGREDIENT`; (5) M-W05-05 convert `CONTAINS_COMPOUND` into PROPOSED assertions + edges with `valueDerivation NOT_STATED` and `basis NOT_STATED` (V-W05-07 passes on derivation but the basis gap remains visible); (6) M-W05-06 Exposure: split `exposureType`/`exposureContext`, rename `INVOLVES` → `HAS_EXPOSURE_AGENT` for Exposure start nodes (`MATCH (e:Exposure)-[r:INVOLVES]->(x) CREATE (e)-[n:HAS_EXPOSURE_AGENT]->(x) SET n.notes = r.notes DELETE r`), compute hashes, redirect duplicates. Each step is idempotent (MERGE on uid/relationshipUid; relabels guarded by `WHERE NOT n:Product`).

GraphQL compatibility: `foodProducts`, `searchFoodProducts` disappear (clients use `products(where: {productKind: CONVENTIONAL_FOOD})`); `exposures.involves` becomes `exposures.agents`; `Lifestyle.intensitySummary`/`exposurePattern` disappear (read the practice's `characterizedExposures`); `FoodItem.containsCompounds` becomes `quantifiedSubstances` with qualifiers; `ExposureAgent` union name changes.

## 5. Ingestion overhead

FDC SR Legacy carries about 100–150 nutrient rows per food; each is one Assertion + one edge (+ locator). For a curated food set of a few hundred foods this is tens of thousands of assertions, acceptable; bulk ingestion uses one CAPTURE activity and one policy adjudication per record (fixture 08 pattern). Ingest only nutrients a CQ needs (default: the constituents named by studies or products in the graph); do not mirror FDC.

## 6. Tested here (not deployment evidence)

Embedded Neo4j 5.26.31 Community: fixtures 01–06 + 08 load with zero errors and zero no-op statements; W05 validation returns zero rows on the clean load and exactly the intended rows after fixture 07; the GraphQL fragment builds under 7.6.3 with stubs and round-trips Exposure/FoodItem/Lifestyle queries. `operations.cypher` was executed on the same store before the fixtures and the probe file afterwards (results in `08-completion-report.md`); Enterprise existence constraints unverified.
