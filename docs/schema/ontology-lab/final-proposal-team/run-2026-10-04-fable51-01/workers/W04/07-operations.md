## 2. Retrieval patterns

- QS-2b / Q-W04-01: `(:ProductVariant {uid})-[r:HAS_FORMULATION_VERSION]->()` filtered on `r.recordedFrom`/`r.recordedTo` and valid bounds, with `lastObservedAt` from the authorizing assertion's locators. Q-W04-02 adds `firstObservedAt` because label-derived episodes rarely state bounds (fixtures 02 and 04: `OBSERVATION_ONLY`).
- CQ-ID-02 / Q-W04-03: the administration interval comes from the study's `STUDY_CONDUCTED_DURING` assertion with MONTH precision widened to the end of the month. A version whose start is unknown and whose first observation is after the interval is classified `START_UNKNOWN_FIRST_OBSERVED_AFTER_INTERVAL` and never offered as "the" formulation.
- CQ-AX-25 / Q-W04-07: traverse `HAS_FORMULATION_VERSION` (believed slice) → component → `USES_MATERIAL` → `REALIZES_SUBSTANCE` assertion; never filter on the derived `CONTAINS`.
- Derived `CONTAINS` / `CONTAINS_COMPOUND_FORM` are regenerated by a projector after every committed `HAS_FORMULATION_VERSION`, `USES_MATERIAL` or `HAS_CHEMICAL_FORM` episode change. The projector runs in its own transaction and deletes and recreates the edges. They are shortcuts and never the only history (V-004, V-W04-02).

## 3. Application validation and transactions (service-enforced)

1. **Formulation write transaction:** create the Assertion, then the payload nodes (or reuse by `payloadHash`), then the episode edge with `recordedFrom = transaction time` (never backdated, INV-502). Then, inside the same transaction, run the DEFINITE-overlap check against the other believed episodes of the same `(variant, jurisdiction)` (V-508 semantics) and abort on conflict. POSSIBLE overlaps (null or imprecise bound) commit and go to the review queue (V-509). Concurrency: take a write lock on the variant node first (`SET v._lock = null` pattern or `CALL { MATCH (v) SET v.updatedAt = v.updatedAt }`) so that two writers cannot both pass the check. Community has no multi-statement constraint for this.
2. **Supersession:** one transaction writes the new Assertion, `SUPERSEDES {supersessionKind, recordedAt}`, `older.recordedTo`, the old episode's `recordedTo` (the only permitted update) and the new episode (V-505, V-506, V-507b).
3. **Immutability:** `FormulationVersion`, `IngredientComponent`, `PackageConfiguration`, `ServingDefinition` and the label artifacts accept no update after commit. The generated GraphQL update mutations still expose their scalar fields (the build in this run confirms `@settable` is applied only to the derived Product fields and the legacy relationship fields). The API layer must reject updates to these types or omit their update mutations (`@mutation(operations: [CREATE])` on these types is a Fable decision; it was not tested here).
4. **Projection guards:** `Product.status`, `approvedYear`, `regulatoryAuthorizationId`, `primaryRegulatoryIdentifier`, `formulationSummary`, `launchYear` and `regulatoryProjectionStatusUids` are written only by the projector (not settable through GraphQL, verified in the generated `ProductCreateInput`).
5. **Classification on ingest:** `amountReferent` from the label-line rule (21 CFR 101.36(b)(2)(ii) nutrient, (b)(3)(ii) listed ingredient, blend total). `massBasis` SALT_FORM only when the line names the salt, MATERIAL_AS_IS when it names a material without one, UNSPECIFIED otherwise. `dailyValueStatus` NOT_APPLICABLE when the panel says "not established". `servingsPerContainer` only on a package label's ServingDefinition.
6. **Calculated amounts:** the calculator writes `ACTIVE_MOIETY_AMOUNT` with `basisKind: CALCULATED`, `derivationRule` naming the molecular-weight source and retrieval date, and `DERIVED_FROM_ASSERTION` to the formulation and `HAS_ACTIVE_MOIETY` assertions (V-W04-04). When a molecular-weight source changes, a new assertion supersedes the old one (`RE_REVIEW`).

## 4. Capability and edition conditions

- Community 5.26.31: uniqueness and range/fulltext indexes work; existence and type constraints do not (service plus V-101/V-W04-12).
- `@neo4j/graphql` 7.6.3: the merged fragment (W04 plus stubs for other owners) builds: 1,320 generated types, 64 queries, 75 mutations, no vector provider configured. Two fields with the same relationship type to different targets (`LabelSnapshot.labelForVariants` / `labelForPackages`; `Product.classifiedAsDevices` / `classifiedAsInstruments`) are accepted. `@settable(onCreate:false, onUpdate:false)` removes the fields from create inputs.
- **Neo4j 5.26.31 query defect found in this run:** `WITH ['A','B'] AS ip RETURN (NOT any(x IN ip WHERE x IN ['A']) OR NOT any(x IN ip WHERE x IN ['B']))` returns `true` (expected `false`). With distinct iteration variable names, or with `=` instead of `IN`, the result is correct. The interpreted runtime gives the same wrong answer. W04 validators use distinct names. All validation queries should be linted for reused list-predicate variables (W04-SR-13).
- Memory: the embedded instance was OOM-killed once while 20 or more worker JVMs shared 16 GB. It was rerun with `-Xmx768m`. Scenario results are from the rerun.

## 5. Idempotence, lifecycle, migration and ingestion overhead

- Fixtures use `MERGE` by uid with `ON CREATE SET` for shared nodes, so they load in any order with `elysium-basis.cypher` and `study-vs-product-mismatch.cypher`. Label sets on `MERGE` must match the other fixtures exactly: `MERGE (:IngredientMaterial:Entity {uid})` against a node created as `:Entity:IngredientMaterial:BrandedIngredientMaterial` creates a duplicate. This was found in scenario B5 and fixed. Production ingestion must `MERGE` on the uid with one label and add the others with `SET`.
- Migration order (details in `migration-map.yaml`): (1) backfill labels, `entityType`/`stateType`/`artifactType` and uids. (2) Convert each `CONTAINS_COMPOUND_FORM {DoseMetadata}` edge into a MIGRATION `FormulationVersion` with components, `massBasis: UNSPECIFIED` and an attachment episode with bases UNKNOWN, written by a MIGRATION reviewer. (3) Regenerate the derived edges. (4) Null out `Product.status = 'APPROVED'` values that no APPROVAL status backs, and report them. (5) Make the legacy edges read-only. `fixtures/w04-06-elysium-basis-compat.cypher` is the executable sample of steps 1–3 on the 0.1.0 fixture.
- Overhead per label capture: about one snapshot, n locators (one per declaration line), n declarations, k quantity declarations, one or two serving definitions, and 3 + n assertions (HAS_FORMULATION_VERSION, LABEL_FOR, DECLARES_FORMULATION, USES_MATERIAL per component) with their projected edges. A re-capture with an unchanged payload adds only a snapshot, locators and `REANCHORS`: payload hashes match, and the existing assertions gain `SUPPORTED_BY` locators. That is how `lastObservedAt` advances without a new episode.
